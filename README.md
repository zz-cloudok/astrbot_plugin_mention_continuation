# AstrBot Mention Continuation

当群友只 @ 机器人、没有附带正文时，短暂等待对方继续补充内容，再把两条消息合并成一次完整请求。

## 功能

- 检测真实的 QQ `@机器人` 消息，不解析文字形式的别名。
- 单独 @ 后最多等待 10 秒。
- 同一群聊、同一发送者在等待期间发送文字或图片，会与这次 @ 合并处理。
- 等待结束仍无补充时，读取同群最近消息，优先承接紧邻这次 @ 的最后一条正文。
- 用户 @ 并附带正文时，当前正文优先于历史话题、图片摘要和长期记忆。
- 用户近期发图后，再 @ 并明确要求“仔细看”“详细分析”等时，可在 120 秒内重新附加最近最多 4 张原图。
- 命令、@ 其他人和引用回复不会被等待逻辑吞掉。
- 兼容第三方插件包装器对 LLM 请求钩子传入额外参数的情况。

## 不包含文字 @

本插件只识别消息组件中的真实 `At` 对象，并要求其 QQ 号等于机器人自身账号。

以下普通文字不会被当成 @：

```text
@虎
@逢坂大河
@逢坂大大的河
```

如需根据文字关键词唤醒机器人，请使用独立的
`astrbot_plugin_keyword_wake`。

## 等待与合并流程

1. 消息中只有一个 `@机器人`，没有正文。
2. 插件等待最多 10 秒。
3. 同一用户补充文字或图片：合并为一次完整请求。
4. 没有补充：注入同群最近上下文后交给 LLM。
5. 用户先 @，之后发送命令、@ 其他人或引用回复：原事件放行，不吞掉后续消息。

## 安装

1. 下载对应版本的 ZIP。
2. 在 AstrBot 插件管理中上传。
3. 确认插件 `mention_continuation` 已启用。

本插件没有额外配置项，安装后即可工作。

## 兼容性

- 面向 AstrBot `4.x` 开发。
- 已在 AstrBot `4.29.3` 下验证。
- 需要平台消息事件能够提供真实的 `At` 组件。
